# Установка кода и внешнего MemriBoard

В этом репозитории находятся тело эксперимента, общие вычислительные модули, готовые веса, тестовая часть MNIST, карта и исходные измерения. Код MemriBoard устанавливается **отдельным пакетом** в то же Python-окружение. Каталог `vendor`, добавление внешних путей в `sys.path`, динамическая загрузка драйвера и подмена преобразователей не используются.

Проверяемая конфигурация — Python 3.11. Рекомендуется отдельное виртуальное окружение. Все команды ниже выполняются из корня этого репозитория.

```text
git clone https://github.com/alexander-toschev/mnist-memristor-snn.git
cd mnist-memristor-snn
git lfs pull
python -m venv .venv
```

В PowerShell активировать окружение командой ` .\.venv\Scripts\Activate.ps1`; в Linux/macOS — `source .venv/bin/activate`. Либо вызывать Python из `.venv` полным относительным путём без активации.

Для CPU-расчёта GPU не требуется:

```text
python -m pip install torch==2.4.1 torchvision==0.19.1 torchaudio==2.4.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

## Подключение MemriBoard

У проверенной версии публичные импорты называются `manager.board.Connector`, `manager.service.converters` и `simulator.src`. Это имена Python-модулей, а не обещание наличия официального пакета с именем `memriboard` на PyPI. Установите совместимый wheel, предоставленный разработчиком, через `python -m pip install` с путём к файлу. Драйверы для физического устройства устанавливаются отдельно по инструкции поставщика.

Если MemriBoard предоставлен только исходным каталогом без `pyproject.toml`/`setup.py`, можно собрать **локальный** wheel прилагаемой утилитой. Она не изменяет исходники, не скачивает их и не копирует закрытый MemriCORE. Укажите путь к своему разрешённому исходному каталогу вместо `../MemriBoard`:

```text
python -m pip install setuptools wheel
python tools/package_memriboard.py ../MemriBoard --output external-wheels
python -m pip install --no-index --find-links external-wheels memriboard-connector-local
```

Имя `memriboard-connector-local` относится только к этой локальной упаковке. Суффикс версии вычисляется из содержимого исходников. Это не официальный релиз MemriBoard. Wheel и внешний исходный код не публикуются в данном репозитории; `external-wheels/` исключён из Git. Утилита предназначена для интерфейса и симулятора; она не заменяет поставку аппаратных драйверов или GUI-зависимостей.

## Проверка без открытия платы

```text
python verify.py
python experiments/mnist_tiled_transfer_20261022/experiment.py --check-environment
```

Вторая команда проверяет обычные импорты и конфигурацию симулятора, печатает версии и контрольные суммы открытых компонентов. `Connector` не создаётся, порт не открывается. Пакет должен содержать `simulator_settings.ini`, соответствующий `configs/simulator_settings.ini`. Эксперимент не перезаписывает конфигурацию внешнего пакета; при различии нужно установить совместимую поставку. При новом сборе эти сведения сохраняются в манифесте.

## Повторение оценки по сохранённым аппаратным откликам

```text
python tools/restore_terminal_session.py --session 4d2dfee0-3106-40de-9ad8-3d8542bef989
python experiments/mnist_tiled_transfer_20261022/experiment.py --evaluate-session 4d2dfee0-3106-40de-9ad8-3d8542bef989
```

Для модельных откликов заменить идентификатор в обеих командах на `673b05ce-6b5d-475f-b1b5-87f49f9f1e68`. Восстановление проверяет SHA-256 и перечень файлов. Расчёт восстанавливает таблицу откликов из исходных отсчётов с **преобразователями установленного MemriBoard**, затем обрабатывает все 10 000 тестовых изображений на CPU. Плата не вызывается; тестовые метки не используются для изменения весов или классификатора. Сопоставлять точность можно только после `status=completed` и подтверждения `test_images=10000`.

Для быстрой проверки всей цепочки используйте дополнительный флаг `--smoke`. Он обрабатывает 16 изображений; результат помечается `smoke16_not_full_accuracy` и не является воспроизведением полной точности.

## Новый сбор в симуляторе

```text
python experiments/mnist_tiled_transfer_20261022/experiment.py --run-simulator --pilot --acquire-only
python experiments/mnist_tiled_transfer_20261022/experiment.py --run-simulator --acquire-only
```

Первая команда проверяет одну загрузку без оценки точности; вторая выполняет все 134 загрузки. Затем следует `--evaluate-session` с новым идентификатором. Предварительное обучение не повторяется: используются опубликованные STDP-веса. Начальные состояния нового симулятора зависят от установленной реализации, поэтому новая точность должна измеряться заново.

## Аппаратный запуск

После подготовки и проверки устройства оператор может заменить `--run-simulator` на `--run-hardware`. Этот режим изменяет проводимости. Выбор осуществляется штатным `Connector(cb_type='real', board_type=...)`; тип платы и электрические параметры берутся из `configs/board.ini`. Публичный интерфейс, преобразователи и конфигурация MemriBoard используются для всех воздействий. Отобранная карта описывает опыт 23 октября, а не гарантированное сегодняшнее состояние ячеек.

Результаты сохраняются в `results/mnist_tiled_transfer_20261022/UUID/`; прогресс обучения не выводится, поскольку этот эксперимент переносит готовые веса. Выводятся загрузки весов и прогресс тестирования. Автоматическая публикация результатов из Python убрана: программа не содержит привязки к учётным данным или ветке автора.

## Границы поставки

Это воспроизведение переноса и оценки готовой модели, а не повторное STDP-обучение. Оно не демонстрирует физический LIF или работу на потоке изображений в реальном времени. Неизвестные длительность аппаратного импульса, ревизия чипа и закрытые компоненты по-прежнему ограничивают независимый физический повтор. Численный результат на другой версии внешнего пакета нельзя считать тождественным без проверки.
